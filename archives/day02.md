先区分两个量：`logit z_j` 是模型给第 j 个 token 的原始分数，还不是概率；softmax 把所有分数变成和为 1 的概率：`p_j = exp(z_j) / Σ_k exp(z_k)`。正确 token 是 y，损失是 `L=-log p_y`，意思仍是“正确 token 概率越低，惩罚越大”。

把 softmax 代入后，公式会变得很好求导：
`L = -log(exp(z_y)/Σ_k exp(z_k)) = -z_y + log Σ_k exp(z_k)`。

对任意一个 logit `z_j` 求导，有两部分：
- `-z_y` 只在 `j=y` 时有导数，结果是 `-1`；
- `log Σ_k exp(z_k)` 对 `z_j` 的导数是 `exp(z_j)/Σ_k exp(z_k)=p_j`。

所以总结果是：`∂L/∂z_j = p_j - 1[j=y]`。其中 `1[j=y]` 是指示函数：j 是正确 token 时取 1，否则取 0。换成两种情形：
- 正确 token：`∂L/∂z_y = p_y - 1`；
- 其他 token：`∂L/∂z_j = p_j`。

为什么这会让模型纠错？梯度下降更新是 `z_j ← z_j - η·∂L/∂z_j`。
- 对正确 token，`p_y-1` 是负数，因此“减去负数”会让 `z_y` 上升，增量为 `η(1-p_y)`；
- 对错误 token，梯度 `p_j` 为正，因此其 logit 会下降，且当前错得越自信（p_j 越大）压得越多。

softmax 会比较所有 logit 的相对大小。因此正确 logit 上升、其他 logit 下降后，正确 token 的概率会上升。这正是你前面用直觉说的“提高正确字概率”，这里给出了精确公式。

最后看模型极度自信地猜错：若 `p_y≈0`，则正确 token 的梯度 `p_y-1≈-1`。这表示在输出 logit 这一层，正确答案不会因为“概率已经很低”而没有纠偏信号，反而会得到接近最大的、但有上界的上推力度。这对训练初期很重要：随机初始化的模型常把正确 token 概率预测得极低，交叉熵仍能给出明确的纠错方向。严格说，这只保证 logit 层梯度不消失；往更深的网络传时，仍可能因网络结构、初始化或数值问题发生梯度消失/爆炸。

普通 one-hot 标签中，正确 token 的目标概率是 1，所有错误 token 的目标概率是 0。以词表大小 `V=5`、`ε=0.1` 为例，若正确 token 是“天”：
- 普通标签：`q=[1, 0, 0, 0, 0]`；
- 平滑标签：正确 token 的目标变为 `q_y=0.9`，其余每个 token 的目标变为 `0.1/(5-1)=0.025`。

注意：这不是在说每个错误字都“真实有 2.5% 的语义可能性”。它是一个训练正则化：不鼓励模型把单条训练样本拟合成绝对确定的答案。

梯度为什么仍然好算？一般的交叉熵是 `L=-Σ_k q_k log p_k`。而 softmax 有一个常用结论：`∂ log p_k / ∂z_j = 1[k=j]-p_j`。代入可得：
`∂L/∂z_j = -Σ_k q_k(1[k=j]-p_j) = p_jΣ_k q_k-q_j = p_j-q_j`，
因为目标分布 q 的总和为 1。

所以记忆规则从“预测概率减 one-hot 标签”升级为：`梯度 = 预测分布 p − 目标分布 q`。
- 普通交叉熵：正确类为 `p_y-1`，错误类为 `p_j`；
- label smoothing：正确类为 `p_y-(1-ε)`，错误类为 `p_j-ε/(V-1)`。

- 普通交叉熵的正确类梯度是 `0.99-1=-0.01`，梯度下降仍会轻微推高正确 logit；
- 平滑后的梯度是 `0.99-0.9=+0.09`，梯度下降会压低正确 logit。

softmax temperature（温度）是**推理/生成时**给 logits 加的一个缩放系数。模型原始输出是 logits `z`，普通 softmax 为：
`p_i = exp(z_i) / Σ_j exp(z_j)`。

加入温度 `T>0` 后：
`p_i(T) = exp(z_i/T) / Σ_j exp(z_j/T)`。
它不改变 logits 的排序，但会改变概率分布有多尖。

例如三个 token 的 logits 是 `[2, 1, 0]`：
- `T=1`：概率约为 `[0.665, 0.245, 0.090]`；
- `T=2`：先除以 2，分布变平，约为 `[0.506, 0.307, 0.186]`；
- `T=0.5`：先乘以 2，分布变尖，约为 `[0.867, 0.117, 0.016]`。

直觉上：
- `T>1`：候选概率更接近，若再按概率采样，输出更随机、多样；
- `0<T<1`：更偏向最高概率 token，输出更稳定、保守；
- `T→0` 接近贪心选最大概率 token。严格公式里不能令 `T=0`，工程接口把它当作特殊的贪心模式处理。

这和 label smoothing 的关键区别是：label smoothing 在**训练阶段**改目标分布 `q`，因此会改变参数学到什么、梯度如何更新，并可能影响模型的校准和泛化；temperature 在**推理阶段**只重标定当前 logits，不更新模型参数。

所以两者不能互相替代：训练时没用平滑、推理时调高温度，只是把已经学到的分布临时拉平，无法改正训练目标造成的过度自信或错误排序；反过来，训练时用了平滑，仍可在不同任务的生成阶段用 temperature 控制随机性。

`E_p[z]` 读作“在概率分布 `p` 下，`z` 的期望”，就是**按概率加权的平均 logit**。

- `E`：期望（可以理解成大量随机抽样后的平均值）；
- 下标 `p`：用当前的概率分布 `p` 来加权；
- `[z]`：被平均的量是各 token 的 logit。

公式是：`E_p[z] = Σ_i p_i z_i`。

在当前例子中，`z=[2,1,0]`，`p≈[0.665,0.245,0.090]`，所以：
`E_p[z]=0.665×2+0.245×1+0.090×0=1.575`。

直觉是：如果按当前概率随机抽一个 token，反复抽很多次，抽到的 token 所对应 logit 的平均值约为 `1.575`。它只是在那条温度导数里充当“当前 logit 的概率加权平均水平”：高于它的 token 升温后概率倾向下降，低于它的倾向上升。

这属于推导加分项，不是 temperature 的主结论。面试主线先记住：`T>0` 不改变 logit 排序；升高 `T` 会缩小相对 logit 差距，使概率分布更平，从而改变采样结果但不改变 greedy 输出。

1. 解码层：temperature 和 top-p 只是在模型当前已经给出的 next-token 概率分布上，改变分布尖锐程度或删掉一部分候选。它们既不会联网/查数据库，也不会验证“模型刚说的事实是否真实”。

例如模型不知道某公司 2026 年的新报销政策，即使把 temperature 调到 0，也只是更确定地输出它原本最可能的说法，仍可能是旧信息或编造。对重复同理：升温、top-p、repetition penalty 只能降低某些重复 token 的概率；模型若在语义或注意力层面已经陷入“换句话重复”，这些启发式规则不能可靠解决，还可能伤害流畅度。

2. 训练层：先提高模型的默认行为。数据要高质量、去重，并加入“有证据回答”“信息不足时拒答/追问”的样本；SFT 用这类输入—输出对做监督学习。再用偏好数据做 DPO、RLHF 或 RLAIF：让“有依据、简洁、不重复、会说明不确定性”的回答优于“无依据却说得很肯定、反复啰嗦”的回答。

- `Recall@k`：正确证据是否被检索进前 k 条；
- answer correctness：最终答案是否正确；
- groundedness / faithfulness：答案的每项事实是否真能由检索证据支持；

- 拒答准确率：文档没有答案时，是否能正确说“不知道”；

假设 `batch_size B=2`，每条样本右移后的长度都是 `L=5`：

```text
样本 1 x: [今, 天, 天, 气, 很] → y: [天, 天, 气, 很, 好]
```

- **序列维并行**：每条样本内部的 5 个预测位置同时处理；

## Day 2 学习归档｜自回归预训练的数据与训练管线

**完成状态：已完成。** 当前处于「大模型预训练基础」阶段第 2 节；Transformer 主体已是你的已有基础，本节已把训练数据如何真正驱动参数学习补齐。

**已掌握并能复述**
- 自回归目标：基于前文预测下一个 token；`input` 与 `label` 按完整 token 流右移一位对齐。
- 一个 batch 的计算链路：`[B,L] input → mask → logits[B,L,V] → 有效 token 的交叉熵平均 → backward() → optimizer.step()`。
- 训练时序列位置可通过 causal mask 并行计算；推理时同一请求仍需逐 token decode。`batch_size` 的样本维并行与序列位置并行不冲突。
- 三类机制的职责：causal mask 防未来泄漏；padding attention mask 不把 `<pad>` 当上下文；loss mask/`labels=-100` 不把 `<pad>` 当监督目标。
- token packing：短文档以 `<eos>` 连续拼接后切块，label 仍从完整 token 流右移得到；块边界不是监督边界。
- `<eos>` 有语义、应参与 loss；`<pad>` 仅用于张量对齐、通常应从 attention 和 loss 中排除。

**已纠正的关键边界**
判断是否计入 loss，要看该位置的**右移 label**，不是只看输入中是否出现 `<pad>`。例如 `乙 → <pad>` 应忽略；`甲 → <eos>` 应参与监督。连续 packing 中 `<eos>` 是语义软边界；若需严格禁止跨文档注意力，仍要额外构造 document-aware attention mask。
