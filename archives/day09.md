1. **先止损并选 checkpoint**：保留验证胜率最高时的 checkpoint，启用 early stopping；不要按最后一个 epoch 的训练胜率选模型。

## Day10｜偏好数据质量：先判断一条偏好对是否值得训练

今天的目标不是再背 DPO 公式，而是把它变成一套数据判断能力：同一个 prompt 下，chosen 与 rejected 应该只在我们希望模型学到的质量维度上有可解释的差异。若两者同时混入正确性、格式、长度、风格甚至事实前提的差异，训练信号就会变得含糊，模型可能学到投机策略。

先看一个“结构化摘要”任务。要求：输出必须严格是 JSON，包含 conclusion 和 reason 两个字段；结论与理由必须基于给定文本，不得虚构。

{"conclusion":"负面","reason":"商品与图片不符并导致退款，尽管响应快，核心体验仍受损。"}

对，选 B。DPO 关心的不是 chosen 的绝对概率是否提高，而是相对 reference 后，chosen 相比 rejected 是否被拉开。若 rejected 的相对提升更大，偏好间隔反而缩小，方向不对。

可以把单条 pair 的核心量先记成：

```text
margin = [log πθ(chosen) − log πref(chosen)]
       − [log πθ(rejected) − log πref(rejected)]
```

DPO 希望这个 `margin` 变大：第一项越大越好，第二项越小越好。reference 是锚点，用来衡量当前模型相对原模型到底偏移了多少。

对，选 B。这里的“混淆”指：**真实状态是 A，但模型预测成了 B**。把每条验证样本的人工金标（真实标签）与模型输出（预测标签）交叉计数，就得到混淆矩阵。

例如 300 条验证样本，行为真实状态，列为模型预测：

```text
真实 \ 预测       已退款  退款处理中  unknown
已退款                 86        8        6
退款处理中              5       88        7
unknown                 2        3       95
```

- 对角线（86、88、95）是预测正确。
- 非对角线是混淆。例如真实为“退款处理中”，却预测成“已退款”的有 5 条；这就是 `processing → completed` 的方向性错误。
- 该方向的混淆率要明确分母。若关心“真实处理中时被误报为已退款的风险”，计算：`5 / (5 + 88 + 7) = 5%`。
- “退款处理中”这一类的召回率是：`88 / (5 + 88 + 7) = 88%`，表示真实处理中样本被正确识别的比例。
- 若关心模型输出“退款处理中”时有多可信，则精确率是：`88 / (8 + 88 + 3) ≈ 88.9%`。

对退款这种高风险字段，不能只报总准确率 `(86 + 88 + 95) / 300`；应单独报告容易造成错误业务结论的方向，例如 `退款处理中 → 已退款`、`unknown → 已退款`。

## 已掌握

1. **状态与证据契约**
   - 有明确完成证据（如“退款已原路退回”）才输出 `已退款` 并绑定可定位 evidence。
   - “会在 3–5 个工作日退回”支持的是 `退款处理中/将退款`，不等于已退款完成；若 schema 没有该枚举，必须先补齐业务映射，不能硬标。
   - 没有状态证据时输出 `unknown + 空 evidence`，避免编造；但不能把 `unknown` 当作回避已知事实的万能答案。

2. **数据质量与切分**
   - 金标不清、证据不足的样本应复核、修正或剔除，不能强行充当正例。
   - 训练样本应同时覆盖“有证据 → 具体状态 + evidence”和“无证据 → unknown + 空 evidence”，比例依据线上分布与风险目标确定。
   - 同一工单、改写、近重复应按 `source_ticket_id/source_document_id` 整体 group 切分；随机切分的高分可能由泄露抬高。

3. **评测与验收**
   - 分开监控有证据抽取正确率、`已退款 → unknown` 遗漏率、无证据编造率，以及 `退款处理中 → 已退款` 等方向性混淆。
   - 混淆矩阵中，行是真实金标、列是模型预测；方向性错误率的分母是该真实类别的全部样本。
   - 硬门槛独立生效，不能用总分或平均值抵消：例如处理中的退款误报为已退款 ≤2%、已退款漏为 unknown ≤10%、JSON 合法率 ≥99%。

4. **实验归因与输出工程**
   - 从同一最佳 checkpoint 出发，固定 group 切分、模板、解码、训练预算与评测；每轮只验证一个主要变量。
   - JSON 合法率是独立验收项。围栏等格式失败要先分型，再做单变量修复。
